# Wildlife Dev Bridge Workflow

The provider is part of the owner-controlled `Herds.dll`; no adapter DLL is distributed. The owner targets DevBridge protocol 10 and uses the current `RimWorldDevBridge/DevTools/devbridge.ps1` client. Build the gameplay module, regenerate exactly one loaded-module manifest, and validate its exact identity, MVID, length, hash, command modes, mutation classifications, and execution budgets. Discover the live bridge and query `Lan.Wildlife` context before testing. For a coordinator-owned sandbox request `restart request --agent-id <id> --package-id Lan.Wildlife --readiness game --save-policy none`; attached/live processes require a person or external orchestrator. A Herds change requires fresh context and discarded leases, cursors, handles, and cached state after restart.

The legacy Wildlife-owned file/TCP transport is disabled by default. `BridgeAdapterInfo`, `BridgeCommandSpecs`, and `ExecuteBridgeCommand` remain because the loaded owner manifest uses them. Set `WILDLIFE_ENABLE_LEGACY_BRIDGE=1` only for explicit compatibility testing of the old transport.
